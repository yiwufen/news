# 项目共享规范

本文件是 Claude Code 与 Codex 共用的项目级规则真源。涉及架构、数据契约、开发约束、测试要求与进度维护时，统一以本文件为准。

## 1. 项目目标与架构

项目目标：构建一个面向金融风险研判的 Agent 系统，从非结构化新闻中提取结构化情报，并支持按需分析。

核心架构采用双模式：

- 持续运行模式：新闻入库 -> Worker 提取情报微粒 -> Integrator 同步图谱
- 任务驱动模式：用户查询 -> 意图解析 -> 检索情报微粒/文章 -> Master 分析 -> Critic 校验

核心理念：

- 先检索过滤，再调用高成本推理
- 通过时间切片和并行 Worker 压缩长文本
- 以实体为主线组织检索、图谱和风险传导

## 2. 运行方式

主要运行入口保持不变：

- `run_continuous(graph_enabled=True)`：持续运行模式
- `run_pipeline(raw_query=\"...\")`：任务驱动模式

默认工作流：

1. 持续运行模式先将新闻加工为情报微粒
2. 任务驱动模式优先检索情报微粒
3. 若情报微粒不足，再回退到原始文章检索

## 3. 核心数据契约

`IntelligenceParticle` 是核心结构化输出，至少包含：

- `metadata`：来源、事件时间、可信度
- `risk_signal`：事件类型、风险等级、描述
- `graph_updates`：节点与边的增量图谱信息
- `traceability`：来源文档与冲突状态

约束：

- Worker Agent 的输出必须遵循结构化 Schema，不依赖自由文本约定
- `event_time` 表示事件发生时间，不是报道发布时间
- 结论必须可溯源；无法溯源时应明确承认“证据不足”
- 发现冲突情报时，必须保留冲突状态，不得静默覆盖

## 4. 开发 Guardrails

开发过程中统一遵守：

- 使用 `uv` 管理 Python 环境和依赖
- 提交前执行 `uv run pyright .`
- 优先补充或复用现有模块，不随意复制逻辑
- 所有风险推演基于事件时间线，禁止用未来事件解释过去风险
- 图谱关系边必须携带 `valid_from` 时间戳；默认使用事件时间，并以 `source + target + relation + valid_from` 作为关系去重锚点
- Critic 节点最大重试次数为 `2`
- 任何“输入 -> 处理 -> 输出”流程都要记录处理状态，成功与失败都可追踪
- 涉及实体对齐时，优先使用工商注册号等稳定标识；名称模糊匹配仅作辅助

## 5. 测试与验收

基础检查命令：

```bash
uv run pytest
uv run pyright .
```

验收重点：

- 双模式入口可正常调用
- 情报微粒 Schema 与流程约束不被破坏
- 文档引用统一指向本文件，不再把 `CLAUDE.md` 当项目级真源

## 6. 进度维护

完成任何功能开发后，必须同步更新 `PROGRESS.md`：

- 更新对应模块的完成状态
- 补充新增能力或约束
- 若新增的是项目级规则，也要同时回写到本文件
